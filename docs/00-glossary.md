# 00 — Glossary: every term, in plain language

**Prerequisites:** none. **Learning goal:** never be stopped by a word.
Every term used anywhere in this repository is defined here with an
everyday analogy. Terms are grouped by theme; within a theme they build on
each other, so reading a whole section in order is a short course.

## Shared ideas

**Case** — one scan or one slide with everything that belongs to it: the
image, its geometry, any reference outline, its metadata. *One patient file
in a filing cabinet.*

**Modality** — the kind of imaging that produced the picture: MRI, CT, H&E
microscopy, fluorescence microscopy. *Photograph, X-ray, ultrasound — all
pictures of a body, made by different physics.*

**Track** — in this project, one of the two modality families the platform
handles: `mri` (volumes) and `pathology` (slides). *Two wings of one
building on a shared foundation.*

**Biomarker** — a measurable quantity that indicates a biological state or
a response to treatment: hippocampal volume, the fraction of tumour cells
that are dividing. *A thermometer reading — a number standing in for
something you cannot see directly.*

**Imaging biomarker** — a biomarker computed from an image. *The
thermometer is a camera.*

**Metadata** — data about the data: when a scan was taken, how big its
pixels are, which stain was used. *The label on the jar, not the jam.*

**Geometry** (of an image) — the information that turns pixel positions
into real-world positions: voxel size and orientation for a volume, microns
per pixel and tile position for a slide. *The scale bar on a map — without
it, "two centimetres on the map" means nothing.*

**Pipeline** — a fixed sequence of processing steps where each step's
output is the next step's input. *A car assembly line.*

**Reproducibility** — running the same code on the same data gives the
same result, on any machine, next year. *A recipe precise enough that two
cooks produce the same cake.*

**Provenance** — the recorded history of how a result was produced: which
data, which code version, which settings. *The chain of custody for
evidence.*

**Research use only (RUO)** — a label meaning the software is for
investigation, not for diagnosing or treating anyone. *A prototype car on
a test track, not a road-legal vehicle.*

**Synthetic data** — data generated by a program to resemble real data,
used when the real thing is unavailable, too large, or private. *A crash-
test dummy: built to behave like a person for the test, never mistaken for
one.*

## Volumetric imaging (MRI track)

**MRI (magnetic resonance imaging)** — a scanner that uses strong magnets
and radio waves to image soft tissue in three dimensions, without
radiation. *A loaf of bread photographed slice by slice, then stacked.*

**CT (computed tomography)** — a scanner that builds 3D images from many
X-rays; excellent for bone and lungs. *The same sliced loaf, photographed
with X-rays.*

**Volume** — a 3D image: a stack of 2D slices. *The whole loaf.*

**Voxel** — one 3D pixel, the smallest cube in a volume. *One sugar cube in
a box of sugar cubes.*

**Voxel spacing** — the real-world size of one voxel along each axis, in
millimetres, e.g. 1.0 × 1.0 × 1.2 mm. *How big each sugar cube actually
is. Get it wrong and every volume you compute is wrong by the same factor.*

**Orientation** — which way the axes of the image point in the patient
(left–right, front–back, head–feet). Written in codes such as RAS
(x → Right, y → Anterior, z → Superior). *Knowing which side of the map is
north.*

**Affine** — the small matrix that combines spacing, orientation and origin
to convert voxel indices to millimetres in the scanner. *The map's
scale bar, compass rose and "you are here" in one.*

**NIfTI** — a file format for volumes (`.nii` or `.nii.gz`) that stores the
voxel data plus the affine. *A photo file that includes its own scale bar
and compass.*

**DICOM** — the hospital standard for medical images: one file per slice,
with rich metadata, in a series that together form a volume. *A shoebox of
individually labelled photos that must be sorted into order.*

**Hippocampus** — a small, curved structure deep in each half of the brain,
essential for forming memories; it shrinks in several diseases. *The
brain's librarian.*

**Resampling** — recomputing a volume on a new grid, e.g. so every case has
1 mm voxels. *Redrawing a map at a common scale so maps can be compared.*

**Intensity normalisation** — rescaling brightness so images from different
scanners share a range. *Adjusting the exposure of photos so skin tones
match across cameras.*

**Denoising** — reducing random speckle while keeping edges. *Cleaning a
smudged window without scratching it.*

**Registration** — aligning one image to another so the same anatomy sits
at the same coordinates. *Sliding two transparencies until the outlines
overlap.* **Rigid** registration allows only rotation and translation;
**deformable** registration also allows local stretching.

**Registration residual** — how much mismatch remains after alignment. *The
gap still visible between the two transparencies — a useful warning
sign.*

**Sliding-window inference** — running a model over a large volume in
overlapping chunks and stitching the results. *Reading a poster through a
magnifying glass, one patch at a time.*

**3D U-Net** — the standard neural network for volume segmentation: a
"U"-shaped architecture that compresses the image to understand context,
then expands it back to draw precise outlines. *An artist who first
squints to see the whole shape, then draws the details.*

**Test-time augmentation (TTA)** — running the model on several slightly
altered versions of the same image (flipped, shifted) and comparing the
answers. *Asking a witness the same question three ways; if the answers
differ, trust them less.*

**Monte Carlo dropout** — randomly switching off parts of a neural network
at prediction time, many times, to see how much the answer wobbles. *Asking
a committee to vote with different members absent each time.*

**Repeatability** — how much a measurement varies when the same thing is
measured again under slightly different but realistic conditions. *Weighing
yourself on three scales on three mornings.*

**Minimum detectable difference (MDD)** — the smallest change in a
biomarker that is larger than its measurement noise, and therefore could be
real. *If your scale wobbles by a kilo, a half-kilo change means nothing.*

**Perturbation** — a deliberate, controlled change applied to an image
(noise, blur, rotation, brightness shift) to test how robust a result is.
*Kicking the tyres.*

## Digital pathology (pathology track)

**Histology / histopathology** — the study of tissue under a microscope;
histopathology is its use to diagnose disease. *Reading the fine print of
a biopsy.*

**Whole-slide image (WSI)** — a glass slide scanned at very high
resolution into one enormous digital image, often 100,000 pixels across.
*A photograph of a football pitch in which you can read the blades of
grass.*

**Tile / patch** — a small square cut from a whole-slide image, typically
224–1024 pixels, because the whole slide does not fit in memory. *One
postcard-sized piece of the football-pitch photo.*

**Magnification** — how much the microscope enlarges: 20× or 40× are the
common scanning settings. *The zoom level.*

**Microns per pixel (µm/px)** — the physical width of one pixel; 0.5 µm/px
is typical at 20×, 0.25 µm/px at 40×. *The slide's scale bar — the
pathology equivalent of voxel spacing.*

**Pyramid (image pyramid)** — a whole-slide file stores the same image at
several resolutions, so a viewer can zoom smoothly. *A map app that loads
the country view, then the city view, then the street view.*

**Level** — one resolution in the pyramid; level 0 is the finest. *Which
zoom the map is showing.*

**H&E (haematoxylin and eosin)** — the standard stain: haematoxylin colours
nuclei blue-purple, eosin colours cytoplasm and connective tissue pink.
*The two inks in almost every pathology picture you have ever seen.*

**IHC (immunohistochemistry)** — a stain that uses antibodies to mark one
specific protein, usually brown (the dye is called DAB), with a light blue
nuclear counterstain. *Highlighting every occurrence of one word in a
book.*

**mIF (multiplex immunofluorescence)** — staining several proteins at once,
each glowing in its own colour channel under fluorescent light, so one
cell can be checked for many markers. *Highlighting five different words in
five colours at once.*

**Channel** — one colour layer of a multi-channel image; an mIF image may
have 4, 12 or 40 channels, each one marker. *One highlighter colour.*

**DAPI** — a fluorescent stain that marks all nuclei; the usual "where are
the cells" channel in mIF. *The highlighter that marks every sentence.*

**Spatial transcriptomics** — measuring which genes are active *and where*
on a tissue section. **10x Visium** captures gene activity at thousands of
spots (each ~55 µm, covering a few cells) laid over a matching H&E image.
*A weather map of gene activity laid over a photograph of the town.*

**Spot** — one measurement location on a Visium slide. *One weather
station on the map.*

**Colour deconvolution** — separating a stained image into its component
stains (e.g. haematoxylin and eosin, or haematoxylin and DAB) as if
un-mixing the inks. *Separating a purple mixture back into blue and red
paint.*

**Stain normalisation** — adjusting a slide's colours to match a reference
slide, so tissue scanned in different labs looks alike. **Macenko** is the
classic method (it estimates the two stain colours from the image itself).
*Colour-correcting photos from different cameras to one white balance.*

**Stain shift / domain shift** — the difference in appearance between
slides from different labs, scanners or batches, which can fool a model
trained on one source. *A recipe tested in one oven behaving differently
in another.*

**Stain augmentation** — deliberately varying stain colours during training
or testing so a model learns not to depend on them. *Training a driver in
rain, fog and night, not only sunshine.*

**Tissue mask** — a map of which pixels are tissue and which are empty
glass, so analysis skips the background. *Cropping the sky out of a
landscape photo before counting trees.*

**Nucleus** — the compartment inside a cell holding its DNA; the part most
stains make visible and the object most cell-counting methods detect. *The
stone in a cherry.*

**Nucleus vs cell vs tissue segmentation** — outlining nuclei; outlining
whole cells (nucleus plus cytoplasm); or outlining regions of a tissue type
(tumour, stroma, fat). *Cherry stones, whole cherries, or the whole
orchard.*

**Cell phenotyping** — assigning each cell a type — tumour, immune,
connective, dead — from its appearance or its markers. *Sorting a crowd
into players, referees and spectators.*

**Positivity** — whether a cell shows a marker above a threshold in an IHC
or mIF channel; the *positive fraction* is a common biomarker. *Which
sentences got the highlighter.*

**Tumour microenvironment (TME)** — the neighbourhood around tumour cells:
immune cells, blood vessels, connective tissue — and how they are
arranged. *The town the tumour lives in, not just the tumour.*

**Pen marks, tissue folds, blur** — common slide artefacts: a pathologist's
marker ink, tissue that folded during preparation, and regions the scanner
failed to focus. *Coffee stains and creases on a scanned document.*

**QuPath, 3D Slicer, Napari, Fiji/ImageJ, OMERO** — widely used open tools:
QuPath for slides, 3D Slicer for volumes, Napari and Fiji/ImageJ for general
microscopy, OMERO for storing and sharing images. This project imports
their outputs and exports overlays they can open.

## Segmentation and its metrics

**Segmentation** — drawing the outline of a structure of interest in an
image, pixel by pixel. *Colouring inside the lines — after first drawing
the lines.*

**Label map / mask** — the image-shaped array that records the
segmentation: 0 for background, 1 (or a class number) for the structure.
*The stencil.*

**Semantic vs instance segmentation** — semantic says *what* each pixel is
("nucleus"); instance also says *which one* ("nucleus #37"), so touching
objects are told apart. *"These are apples" vs "this is apple 1, this is
apple 2".*

**Classical baseline** — a segmentation method built from simple, explicit
rules: thresholding (pixels brighter than X), morphology (fill holes,
remove specks), watershed (split touching objects). It is interpretable and
it is the bar a learned model must clear. *A ruler and compass, before the
power tools.*

**Reference / ground truth** — the expert-drawn outline used to score a
method. *The answer key.*

**Dice coefficient** — overlap between prediction and reference: twice the
shared area divided by the sum of both areas; 1 is perfect, 0 is no
overlap. *How much two overlapping coasters cover the same table.*

**Hausdorff distance (HD, HD95)** — the largest distance between the two
outlines' boundaries; HD95 ignores the worst 5 % to resist single spikes.
*The widest gap between two roughly overlapping fences.*

**Normalised surface distance (NSD)** — the fraction of the boundary that
lies within a tolerance of the reference boundary. *What share of the fence
is within a hand's width of where it should be.*

**Aggregated Jaccard Index (AJI)** — an instance-segmentation score that
credits correctly matched objects and penalises missed, invented and merged
ones, all in one number. *Marking a "find every apple" exam: points for each
apple found, minus points for phantom apples and for two apples circled as
one.*

**Panoptic Quality (PQ)** — detection quality (did you find the right
objects?) multiplied by segmentation quality (how well are the found ones
outlined?). *Did you spot the birds, and how well did you draw them?*

**Per-case failure analysis** — looking at the worst individual cases, not
only the average, to learn how a method fails. *Reading the failed exam
papers, not just the class average.*

## Machine learning

**Machine learning (ML)** — programs that learn rules from examples rather
than being given the rules. *Learning to recognise a friend's handwriting
by seeing lots of it.*

**Deep learning** — ML with neural networks many layers deep; the
workhorse of modern image analysis. *Many rows of pattern-detectors, each
building on the last.*

**Neural network** — a stack of simple mathematical units whose
connections are tuned on examples. *A very large adjustable filter.*

**Training / inference** — tuning a model on examples (training) versus
using it to make predictions (inference). *Studying versus sitting the
exam.*

**Pre-trained model / weights** — a network someone already trained; the
"weights" are its learned numbers, downloadable as a file. *Bringing in an
experienced worker instead of training an apprentice.*

**Foundation model** — a large model pre-trained on huge amounts of data
without task-specific labels, meant to be reused for many tasks. A
*pathology* foundation model was pre-trained on millions of slide tiles.
*A general education that many jobs can build on.*

**Self-supervised learning (SSL)** — training without human labels by
making the model solve puzzles built from the data itself (e.g. match two
crops of the same tile). *Learning a language by reading, with no teacher.*

**Embedding** — a list of numbers a model produces to summarise an image;
similar images get similar lists. *A fingerprint for the picture.*

**Linear probe** — a tiny classifier trained on frozen embeddings; if it
works well, the embeddings already contain the needed information. *Testing
how good someone's notes are by letting a beginner answer questions from
them.*

**k-NN (k-nearest neighbours)** — classify an item by majority vote of its
k most similar known items. *"You are who your friends are."*

**Zero-shot classification** — classifying into categories the model was
never explicitly trained on, by matching images to text descriptions.
*Recognising a "zebra" from the description "a striped horse".*

**Vision-language model** — a model that embeds images and text into the
same space, so they can be compared. *A translator between pictures and
words.*

**Fine-tuning** — continuing to train a pre-trained model on a new task.
*Specialist training after the general education.*

**Augmentation** — creating varied copies of training data (flips,
rotations, colour changes) to make a model robust. *Practising the piece in
several keys.*

**Generative model / generative AI** — a model that produces new data
(images, text) rather than only labels. In this project, generative
components are used for augmentation and for report writing; models that
*synthesise* stains or images are roadmap items. *A painter versus a
critic.*

**Grounded report** — a written summary in which every statement is tied to
a computed number, so nothing is invented. *A journalist who must cite a
source for every sentence.*

**Overfitting** — a model that memorises its training examples and fails
on new ones. *Memorising last year's exam answers.*

**Out-of-distribution (OOD)** — input unlike anything the model saw in
training, where its predictions cannot be trusted. *Asking a French teacher
to grade a Japanese essay.*

**Agent** — a program that uses a language model to decide *which* tools to
call and in what order to complete a task, rather than only answering a
question. *A capable assistant who can open the filing cabinet and run the
analysis, not just talk about it.*

**Model Context Protocol (MCP)** — an open standard that lets agent
software connect to external tools and data through a common interface.
*A USB port for agents: any tool with the right plug fits any agent.*

## Uncertainty, validation and statistics

**Uncertainty quantification (UQ)** — estimating how confident a prediction
deserves to be, per case. *A weather forecast that says "70 % chance".*

**Calibration** — whether stated confidence matches observed accuracy: of
the cases a model called "90 % sure", about 90 % should be right. *A
forecaster whose "70 %" days rain 70 % of the time.*

**Held-out data** — examples kept aside during training and used only for
evaluation. *The exam paper the students never saw.*

**Patient-level split** — ensuring all images from one patient land in the
same split, so the model cannot cheat by recognising the patient. *Not
letting one student sit both the practice test and the exam.*

**Cross-validation** — repeating train/test with different held-out folds
to get a more reliable estimate. *Several exams, averaged.*

**Confidence interval (CI)** — a range that would contain the true value in
a stated fraction of repeated experiments. *"Between 3,100 and 3,300 mm³,
19 times out of 20."*

**Bootstrap** — estimating uncertainty by resampling the data with
replacement many times. *Re-drawing the poll from the same respondents to
see how much the result moves.*

**Stratification** — dividing patients into groups by a characteristic (a
biomarker, an age band) to compare or to enrich a study. *Sorting mail by
postcode before delivery.*

**Endpoint** — the measurement a study uses to decide whether a treatment
worked. *The finish line.*

**Statistical power** — the chance a study will detect an effect if it is
real. *A bigger microscope for smaller effects.*

**Benchmark** — a fixed, repeatable comparison of methods on the same data
with the same metrics. *A race on the same track with the same stopwatch.*

## Spatial biology and graphs

**Spatial analysis** — quantifying where things are relative to each other:
which cell types cluster, which avoid each other, how far immune cells are
from the tumour edge. *Studying the seating plan, not just the guest list.*

**Cell graph** — cells as dots (nodes) joined to their neighbours by lines
(edges), built from nucleus centres by k-nearest neighbours or by Delaunay
triangulation. *A social network of cells.*

**Delaunay triangulation** — a way of joining points into triangles so that
neighbours are connected without long, skinny triangles. *A tidy way of
deciding who counts as a neighbour.*

**Neighbourhood enrichment** — a statistic showing which cell types sit
next to each other more (or less) often than chance. *Whether the
engineers and the designers actually mingle at the party.*

**Co-occurrence** — the probability of finding cell type B within a given
distance of cell type A. *How often a coffee shop is within 100 m of a
bookshop.*

**Graph neural network (GNN)** — a neural network that operates on graphs,
letting each node learn from its neighbours. *Gossip: everyone updates
their opinion from the people next to them, a few rounds in a row.*

**Geometric deep learning** — deep learning on non-grid data such as graphs
and point clouds. *Neural networks for maps of relationships, not pixels.*

**Feature aggregation baseline** — the simplest tissue-level model: average
(or count) the per-cell features and feed a plain classifier. The GNN must
beat it. *Judging a party by the average guest, before considering who
talked to whom.*

**Multi-modal learning** — learning from two kinds of data at once, such as
an image and gene-expression measurements at the same location. *Reading
the photograph and the caption together.*

## The audit layer

**Audit** — in this project, a per-case check of whether a segmentation and
the biomarkers built on it can be trusted, computed without a reference
outline. *A proofreader for the model.*

**Reference-free** — computed without an answer key, because in deployment
there is none. *Judging a translation without the original.*

**Trust score** — the audit's estimate, from 0 to 1, that a case's result
is correct. *A credit score for a segmentation.*

**Plausibility rule** — a simple sanity check with a hard bound: a
hippocampus cannot be 20,000 mm³; a tile cannot contain 40,000 nuclei.
*"If the recipe says 40 eggs, something is wrong."*

**Review queue** — the ordered list of cases the audit recommends a human
look at, least trusted first. *The triage line at a clinic.*

**Review budget** — the fraction of cases a reviewer can afford to inspect;
the audit picks the least trustworthy cases up to that budget. *"I have time
for ten of these today — give me the ten that need me most."*

**Operating point** — the threshold on the trust score that separates
"accept" from "review", chosen to match the review budget. *Where you draw
the line.*

**Verdict** — the audit's decision for a case: `accept`, `review` or
`reject` (implausible; do not use). *Pass, look again, or discard.*

## Engineering

**Command line / terminal / shell** — a text window where you type
commands; **bash** on macOS/Linux, **PowerShell** on Windows. *Talking to
the computer by typing instead of clicking.*

**Python** — the programming language this project is written in.
**Package** — a folder of Python code that can be installed and imported.
**Virtual environment (`.venv`)** — a private copy of Python and libraries
for one project. *A sealed toolbox per project.*

**Dependency / pin** — a library the project needs; a pin fixes its exact
version so installs are identical. *A parts list with part numbers.*

**Configuration (config)** — the settings that steer a run, kept in a file
so they can be versioned. *The dials on the machine, written down.*

**Schema / data contract** — the declared shape of a piece of data: fields,
types, allowed ranges. **JSON Schema** is a machine-readable description of
one. *A customs form.* **pydantic** is the library that enforces them.

**Track configuration** — the `tracks:` block of the config: one entry per
modality family, each switchable on or off, each with its own datasets and
resampling target. *Two thermostats in one house.*

**Modality registry** — the lookup table in `modality.py` of every kind of
image the platform knows, marked implemented or planned; what
`imagingagent modalities` prints. *A menu that also lists "coming soon".*

**Discriminated union** — a field that can hold one of several shapes,
with a tag (`kind`) saying which. Geometry is one: `volume` or `tile`.
*An envelope labelled "photo" or "letter" so you know how to open it.*

**Validator** — a rule that runs when a record is created and rejects it
if fields disagree (an H&E case on the `mri` track). *The customs officer
who reads the form.*

**Extras** — optional groups of libraries declared in `pyproject.toml`
(`mri`, `pathology`, `serve`) so the core installs light and each track
adds its own. *Buying the lens kit only when you need the lens.*

**Lock file** — the complete frozen list of every library and version in
an environment, so installs are identical anywhere. *The recipe's brand
and batch numbers, not just the ingredients.*

**Storage abstraction** — one interface for reading and writing files, with
swappable backends (local disk now, cloud buckets later). *A universal
socket: the appliance does not care which power station.*

**Run ledger** — an append-only file with one line per run recording what
ran, when, with which settings. *A ship's log.* **JSONL** is its format:
one JSON object per line.

**Content hash / fingerprint** — a short string computed from data such
that the same data always gives the same string and any change gives a
different one. *A wax seal that shows if the letter was altered.*

**Git / repository / commit / branch / remote / push / pull** — the
version-control system: a repository is a tracked folder, a commit is a
snapshot, a branch is a named line of snapshots, a remote is a copy on
GitHub, push sends commits up, pull brings them down. *A save-game system
with named save slots and cloud backup.* Explained fully in
[`03-git-workflow.md`](03-git-workflow.md).

**Unit test** — a small program that checks one function gives the right
answer. **pytest** runs them. *A smoke detector for code.*

**Linter / formatter (ruff)** — tools that flag likely bugs and enforce a
consistent code style. *Spell-check and a style guide.*

**Continuous integration (CI)** — automatically running the tests on every
push, here on Windows, macOS and Linux. *A robot that checks every change
on three machines you do not own.*

**Container (Docker / Podman)** — a packaged, self-contained environment
holding the code and everything it needs, so it runs identically anywhere.
*A shipping container: same box on any ship or truck.*

**GPU / CPU** — the graphics processor (fast for neural networks) and the
general processor (what every laptop has). This project runs on CPU by
design and documents a free GPU path. *A racing car versus a reliable
family car — this project is built for the family car.*

**HPC (high-performance computing)** — a shared cluster of many machines
with a scheduler that queues jobs. *A laundromat with a queue for the
machines.*

**Architecture decision record (ADR)** — a short document recording one
design decision, its context and the alternatives rejected. *Meeting
minutes for a choice, so nobody re-argues it next year.*

**Streamlit** — a library that turns a Python script into a web page with
buttons and sliders. **CLI** — the command-line interface. **API** — a
set of functions or web endpoints other programs can call. *Front doors of
different shapes into the same house.*
